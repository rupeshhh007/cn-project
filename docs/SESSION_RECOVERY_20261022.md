## Implemented behavior and ownership

`apps/coordinator/src/app.ts` owns membership, admission and authorization. Authenticated `/resume` retains peer/room identity, rotates an authoritative generation, clears the old receipt key and incident link observations, closes the old socket, and broadcasts the restart. Resume attempt IDs make a lost-response retry idempotent. It does **not** alter permitted edges or create routes. `/session` validates a reconnecting capability. Both old socket close **and message** handlers are guarded against replacement races.

Hosts receive an authoritative `pending-requests` snapshot on every socket connect and admission mutation; periodic server cleanup also reconciles expiry. A host-only pending endpoint and reject endpoint share the same state. Approve is idempotent; reject cannot revoke an already admitted peer. Only 20 *pending* requests count toward the limit, at most 20 rejected tombstones are retained, and all claims expire after 15 minutes. Approved sessions remain bounded by the existing eight-peer room limit. A per-tab UUID deduplicates retries; it is not an anti-abuse replacement for invitation/host authorization.

`apps/web/src/lib/room-session.ts` persists only a version, room ID, peer ID, session bearer capability and an optional resume-attempt ID in origin-scoped **sessionStorage**. A separately bounded pending-claim record permits waiting-screen reloads. No localStorage, signing private key, host token or invitation is persisted. The host capability/invitation is reacquired from the authenticated server response. `navigator.locks` gives the active document exclusive ownership of that peer within its browser storage partition, including StrictMode replay. A cloned tab must use its original owner or a fresh invitation. Browsers without Web Locks require explicit Resume confirmation; cross-browser token theft/replay is not solved by local locks.

`App.tsx` validates stored state with the coordinator before adoption, clears transient UI/route/history state, republishes a fresh signing public key, reconnects signaling with bounded exponential delay, handles heartbeat deadlines, and reconciles allowed RTC edges. Transient signaling loss does not dispose a still-working RTC/router/transfer stack. Authenticated replacement stops reconnect contention. Expired server state gives a new-room/fresh-invitation message. Timers, pending fetches, poll loops, managers and routers are cleaned up on lifecycle exit. Admission polling is non-overlapping, abortable and deadline bounded; it is claim delivery, not the host synchronization mechanism. Failed REST approval now produces recoverable feedback instead of an unhandled rejection.

`PeerManager` rebuilds failed/closed channels, bounds stalled negotiation and rejects callbacks from old managed connections. `DistributedRouter` accepts generations only from authenticated coordinator membership, resets that peer's LSA/report watermarks, and rejects old-generation control/data packets. Data packets bind both endpoint generations so queued pre-reload messages cannot enter a fresh receiver incarnation; ACKs reverse those bindings. An endpoint restart terminally fails its outstanding messages; a relay restart still permits bounded alternate-route retry. Existing duplicate/late-ACK/dead-neighbor protections remain enabled.

`TransferManager.peerRestarted` interrupts only active transfers whose **endpoint** refreshed, discards receiver assembly/sender buffers, releases slots and reports an honest failure. A relay-only restart does not falsely cancel an endpoint transfer that can recover through another route. Downloads, conversations, journal history and active transfers are **not** durable across reloads.

## Security and remaining limits

The persisted bearer is a deliberate same-origin per-tab capability, still accessible to same-origin JavaScript/XSS and anyone controlling that browser profile. Local locks prevent accidental same-partition clones, not malicious replay from another device. Trusted HTTPS, private room invitations, host-only admin checks, ephemeral signing keys, signed transfer receipts, SHA-256 and resource bounds are preserved. Room and peer identifiers are public protocol identities; exports must never include stored credentials, claims, QR data or keys. Invitation parameters are removed from the address bar on admission; existing request-log query redaction remains in force.

Coordinator rooms remain memory-only. A server restart expires them; a changed origin/IP does not inherit the old origin's sessionStorage. Closing a tab may discard storage, unlike reloading it. Background phones may suspend timers, channels and relaying; foreground operation remains required. Revoked edges are never silently restored. Chat/control-plane remains cooperative (not Byzantine-secure); relay payload encryption is hop-by-hop, not application end-to-end encryption. Files retain signed source-routed envelopes selected from locally learned LSAs. Final two-laptop/two-phone browser-failure acceptance and repeated equal-payload strategy comparisons remain pending.
